        Wow moment 3

        Prices find value

        Nobody tells the agents what a turn is worth, and bids never change. Yet in each situation, the winning bid should settle at or just below what winning there actually earns (Theorem 1). Here is the live economy above, situation by situation.

        Average winning bidAverage earned by the winner

        earned by a win = what the next agent pays + any reward

        If an agent bids more than it earns, it loses credits every turn and goes broke. If it bids less, it gets rich and gets copied, and the copies bid a little higher. Prices get squeezed toward value.

        Adds a lazy planner that bids 40 above the top planner (Lemma 2). It wins every empty-workspace auction, loses credits each time, and goes broke.

        What changed inside the agents

        TraitStartEnd

        Same as the paper: executors absorbed checking. Their habit of re-checking their own steps rose sharply, like the paper's executor that took over the verifier's job. On easy problems the planner is often skipped altogether (E then A).

        Different: on harder problems the workflows got longer, not shorter. The answer agent always wakes after an executor (a rule in the released code), and learned to wait. So "not ready yet" turns now sit between steps (P E A E A E A), where the paper saw verifier turns drop out.

        Real AI mode

        Same economy, real AI agents. Each agent is a Claude prompt: a fixed role prompt plus a strategy prompt that evolves. Wake-up, work and prompt rewriting are all real model calls, using prompts adapted from the authors' code. The problems are real MATH competition problems with whole-number answers, marked exactly.

        Tests

        38 tests, at least one per rule, including my article's ledger. The real AI mode's plumbing has its own test with a stand-in model. The last tests run hundreds of training runs, so they take a few seconds.

          What the toy version is not

          • Its agents are not language models. A "prompt" is a wake-up list plus one or two numbers, and the task is a made-up multi-step problem where each step succeeds with some chance. So it can test the economics, not reasoning.
          • Its prompt rewriter is a rule: copies get small random changes, repairs fix the weakness the failure trace shows. A real model can invent new strategies. Mine cannot.
          • Toy settings I chose: the step success rates per level, how much a plan helps, the starting team's skill ranges and how big a repair is. Everything economic comes from the paper or the released research config.
          • No literature role, no tools, no cross-domain transfer, no generalist agent.

          Where the paper and the code differ

          • Reward: Eq. 1 pays only the final actor on success. The research config pays everyone on the path, and charges them all when the answer is wrong.
          • Bankruptcy: the code uses below zero (Sec. 2.3). Alg. 1 says zero or less.
          • Bids: the research config uses fixed, so every veteran ends up with the same bid.
          • Refill: Alg. 1 mutates a starting agent. The code mutates the richest.
          • Rollback: the code restores survivors' wealth after every bankrupt trial, including the last one.
