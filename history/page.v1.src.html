    Same: the full system beats every version with a part removed, in both.

    Different: the paper's worst cut is exploration. Here it is exploitation. The likely reason is how "amend" works. In the paper, an LLM rewrites a failed agent's prompt using its failure trace.       Tests

      30 tests, one or more per mechanism, including my article's ledger (12, 13, 13 and 12, 13, 3). The last three run hundreds of seeded economies, so they take a few seconds.

        What this rebuild is not

        • No language models. An agent's prompt is replaced by one number, its skill. So none of the paper's scores (MATH, finance, CloudCast) can be reproduced here.
        • The improving is done by mutation, which is skill plus random noise. The economy only decides which variants survive. That is selection, and it is the part the paper credits to the market.
        • Amending a failed agent draws a new random skill. The paper's LLM uses the failure trace. That is the gap I expect explains the different ablation order.
        • The toy task is a fixed three-step chain. Roles, topology changes and transfer to new problems are not modelled.
        • I changed the rent and birth schedule after a first run plateaued at about 30%. The reason: CloudCast's schedule is per episode of up to 22 auctions, my task has 3. Scaling to 21 auctions fixed it. Both runs are in my build notes.

        Where the paper and the code differ

        • Bankruptcy: code uses below zero (Sec. 2.3), Alg. 1 says zero or less.
        • Reward: Eq. 1 pays the final actor. Released configs can pay each step and split it along the recent chain.
        • Bids: the research config uses fixed, so every veteran settles to the same bid and the auction becomes a coin flip among them. Flip the switch above to see it.
        • Replenish: Alg. 1 mutates a starting template, the code mutates the richest agent.

        Something to watch for

        • Most births land in the Check column. Copying the richest agent favours the role that collects the reward. Diagnose and Edit mostly improve through exploration and bankruptcy. The paper also reports births piling up in a few roles (App. E.7).
