      Each lane runs 8 economies. The dots show one of them. The line and the number average all 8, because one seed alone is noisy.

      This rebuild, toy task

      The paper, finance task

      Table 2, Finance-Agent-Bench, mean accuracy %. A different task and different units, so compare the order, not the size.

      Same: in both, the full system beats every version with a part removed.

      Different: the paper's worst cut is exploration. Here it is exploitation. My best explanation: in the paper, an AI rewrites a failed agent using what went wrong. Here, a replacement just gets a random skill. So exploration is blind in my version, and copying the rich does more of the work.

      Wow moment 3

      Prices find value

      Nobody tells the agents what a turn is worth. Bids are fixed at birth. Yet the winning bid at each step drifts toward the true value of that step. The paper proves this (Theorem 1). Here it is, live from the economy above.

      Price (winning bid)Value of the turn

      value of a turn = skill x what the next agent pays

      If an agent bids more than that, it loses credits every turn and goes broke. If it bids less, it gets rich, gets copied, and its copies bid a little higher. So prices are squeezed toward value from both sides.

      Rent keeps prices a little below value. In my 30-seed run, 97% of late prices sat at or below value.

      Adds a clumsy Diagnose agent that bids far above value (Lemma 2). Scroll up and watch it win every Diagnose turn, bleed credits, and die.

      Tests

      30 tests, at least one per rule, including my article's ledger (12, 13, 13 and 12, 13, 3). The last three run hundreds of seeded economies, so they take a few seconds.

        What this rebuild is not

        • There is no real AI inside. An agent's prompt is replaced by one number, its skill. So the paper's scores (MATH, finance, CloudCast) cannot be reproduced here.
        • Mutation (skill plus random noise) does the improving. The market only decides which variants survive. That selection is the part the paper credits to the economy.
        • A replacement agent gets a random skill. In the paper, an AI rewrites it using the failure. I think this explains the different ablation order.
        • The task is a fixed three-step chain. Changing workflows and transfer to new problems are not modelled.
        • I changed the rent and birth schedule after a first run plateaued near 30%. CloudCast's schedule is per episode of up to 22 auctions, and my task has 3. Scaling to 21 auctions fixed it. Both runs are in my build notes.

        Where the paper and the code differ

        • Bankruptcy: the code uses below zero (Sec. 2.3). Alg. 1 says zero or less.
        • Reward: Eq. 1 pays the final actor. The released configs can pay each step and split it along the chain.
        • Bids: the research config uses fixed, so every veteran ends up with the same bid and the auction becomes a coin flip. Try the "Everyone bids the same" switch.
        • Refilling the team: Alg. 1 mutates a starting agent. The code mutates the richest.

        Something to watch for

        • Most births land in the Check column. Copying the richest agent favours the job that collects the reward. Diagnose and Edit improve mostly through bankruptcy and replacement. The paper also reports births piling up in a few roles (App. E.7).
